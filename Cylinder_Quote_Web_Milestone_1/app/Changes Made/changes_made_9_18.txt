Diagnosis before further fixes:

- New Accept Request is populated by `app/portal.py` in `employee_dashboard()`.
	It currently selects every unassigned quote with status `new` or
	`pending_approval`. `app/quote_service.py:create_quote_snapshot()` assigns
	status `new` for both customer and employee-created quotes, so employee/admin
	quotes can enter New Accept Request. The employee-created quote path needs a
	role-aware status/queue rule so a quote-only employee quote is pending approval
	and never a new acceptance request.
- Pending Approvals in `employee_dashboard()` currently selects assigned
	`accepted`/`pending_approval` quotes and orders them by `created_at.asc()`.
	This is the opposite of the requested last-saved/last-modified descending
	order. The owning timestamp is `edited_at`, with `created_at` as fallback.
- The employee Quote Form `createNewOrder()` calls `saveQuote(false, true)` for
	an existing quote. `saveQuote()` first PATCHes the quote and then POSTs the
	order, which explains why Order behaves like Update. The actions need separate
	request paths while preserving the order snapshot and pricing authority.
- Order Form startup fetches `/api/quotes/<id>`, then awaits the tie-rod JSON,
	then awaits the engineering JSON. These independent reference loads are
	serialized in `app/Order_Form/order_form.js`, making the page wait for all
	three before rendering.
- Server-side Order Form tests currently prove that `order_form_parts` contains
	`unit_price` and extended `cost`. The browser renderer only sets its internal
	unit-price cache when a row has a nonblank price or identifying data; a blank
	displayed Cost therefore needs a captured failing row/data payload before a
	calculation change is justified.
- The Inventory Manager in `app/Parts_catalog_page/parts_catalog.html` currently
	renders inventory, allocated, on-order, and source columns but no allocation
	formula display. The requested mild formula text is a new Inventory Manager
	presentation field only; no pricing calculator or Order Form formula should
	be changed.
- Customer autocomplete is currently in the requested state: `app/web.py` uses
	only company name, legacy name, and POC with `%query%` substring matching, and
	`app/static/app.js` starts requests at two characters with a 250 ms debounce.
	No current source evidence shows a reversion in this path.
